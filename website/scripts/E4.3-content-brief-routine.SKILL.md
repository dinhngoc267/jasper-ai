It is Sunday evening. Use TODAY'S actual calendar date wherever this prompt says YYYY-MM-DD (compute it at run time — do not hardcode).

Project root: `~/code-projects/jasper-ai`. Honor `~/.claude/rules/global-engineering.md` at all times: run `git status` before file work, stage files explicitly by name (never `git add .` / `git add -A`), never push to `main` directly, never `--no-verify`, and open a PR for review rather than merging.

**This routine PROPOSES; it never publishes.** It stops at an open PR. Nothing is written into the writer's auto-queue — and no content is ever written — until the operator merges the brief PR. Human approval is the gate.

## Step 1 — Read the channel signal

```bash
cd ~/code-projects/jasper-ai/website
node scripts/channel-signal.mjs
```

This queries the live Supabase project directly (service key from `website/.env.local`) and prints the ranked `how_they_heard` breakdown, the top channel (or an explicit tie), an honest confidence verdict, and the recommended content-strategy entry. It also emits a machine-readable `<!-- CHANNEL_SIGNAL_JSON: {...} -->` blob on the last line — parse that blob and read:

- `recommendedChannelKey` — the channel to bias toward (or `Fallback`).
- `confidence` — `"strong"`, `"weak"`, or `"tie"`.
- `strategy` — `{ format, angle, keywordApproach }` for the recommended channel.
- `topChannel` / `tiedLabels` / `runnerUp` / `margin` — the supporting numbers.

**Trust the confidence verdict.** If `confidence` is `"weak"` or `"tie"`, the script has already resolved `recommendedChannelKey` to `Fallback` (evergreen positioning) — do NOT override it to force a channel angle the data doesn't support. If `"strong"`, bias the brief toward that channel using its `strategy`.

## Step 2 — Author a COMPLETE content brief

Read `docs/product/product-plan.md` for business context (what Jasper AI sells, ICP, positioning, tagline "AI systems that ship"). Then choose a short kebab-case `{slug}` for the topic and author `content/topics/{slug}/brief.md`.

The brief's topic/angle/format MUST reflect the recommended channel's `strategy` (or, if the signal is weak/tied, state that plainly in the brief and default to evergreen positioning — do not pretend a channel signal exists). Example: a `strong` `LinkedIn` signal → an opinion/contrarian-take angle for a professional audience; a `weak`/`tie` signal → an evergreen positioning post.

The brief MUST include EVERY required field from the writer's brief format (`~/.claude/agents/writer.md`) — an incomplete brief makes the writer stop and ask, defeating the automation. Required fields, all filled with real content (no placeholders):

```markdown
# Post Brief

**Title**: [concrete working title reflecting the channel angle]
**Target keyword**: [one primary keyword, per strategy.keywordApproach]
**Audience**: [specific ICP — founders/teams wanting AI agents, RAG, custom LLM apps, or AI strategy]
**Angle**: [the unique claim/POV — must match strategy.angle for the detected channel]
**Hook idea**: [a surprising stat, claim, or question to open with]
**Supporting points**: [3–5 bullets of what to cover]
**Call to action**: [one specific action, e.g. "Book a 30-min scoping call"]
**Tone**: [e.g. authoritative, conversational, technical — fit the channel]
**Deadline**: next Monday run
```

At the bottom of the brief, add a short provenance note stating which channel drove it and the confidence level, e.g.:

```markdown
---
_Channel-bias provenance (E4.3): recommended channel `Referral` at STRONG confidence
(Referral 12 vs LinkedIn 6, margin 6). Generated by content-brief-weekly on YYYY-MM-DD
from `node website/scripts/channel-signal.mjs`._
```

## Step 3 — Commit on a branch and open a PR (no auto-merge)

```bash
cd ~/code-projects/jasper-ai
git status
git pull origin main
git checkout -b content/brief/YYYY-MM-DD-{slug}
git add content/topics/{slug}/brief.md
git commit -m "content(brief): {slug} — channel-biased ({channel})"
git push origin content/brief/YYYY-MM-DD-{slug}
gh pr create \
  --title "content(brief): {slug} — channel-biased ({channel})" \
  --base main \
  --body "Proposed channel-biased content brief (E4.3). Driven by channel **{channel}** at **{confidence}** confidence — {one line on the numbers, e.g. Referral 12 vs LinkedIn 6}. If the signal was weak/tied, this defaults to evergreen positioning by design. Needs human review: merging this brief is what releases it into the writer's queue for the Monday writer run. Do NOT merge if the angle looks wrong for the channel."
git checkout main
git branch -d content/brief/YYYY-MM-DD-{slug} 2>/dev/null || true
```

Replace `{channel}` with `recommendedChannelKey` and `{confidence}` with the confidence verdict from Step 1.

**Do NOT auto-merge** — same convention as `writer-weekly` and `dashboard-baseline-weekly`. The open PR is the deliverable. The writer (`writer-weekly`, Monday 9:03 AM) will only pick up the brief once the operator has merged it to `main`; until then it exists solely on the PR branch and enters no auto-queue.
